# Product direction

Project Steward first: project judgment, follow-through and simple conversation. Eve hosts Steward. Anthropic-hosted Claude Code, triggered through Routines, is its coding partner on subscription allowance.

One approved project brief, one active coding job, and an owner-visible approval and evidence loop come before more bots. Do not build a hosted coding CLI, credential proxy, or automatic paid API fallback. Keep provider observations separate from worker reports.

## Boundaries

Owner-authenticated actions bind exact project revisions and task scope. Persist dispatch intent before one external request. Lost responses may mean execution started; reconcile instead of retrying. Pause blocks new admission but is not proof of remote cancellation. Keep credentials out of task payloads and repository-executed environments.

Public source and private runtime state are separate. The public repository does not grant access to a hosted workspace, account, model allowance or live coding routine. Budgets and account changes require owner authorization. No merge or deployment is implied by a coding assignment.

## Learning and milestones

1. Complete one real Steward proposal → exact approval → managed coding → tested draft PR loop.
2. Improve recovery, useful status, bounded quiet follow-up, and trace-based evaluation.
3. Measure a personal pilot: useful outcomes, interventions, failure classes and observed cost.
4. Add SMS or a second bot only when the first loop shows a practical need.

Representative evals cover missing/conflicting context, stale approvals, duplicate input, unknown dispatch, subscription exhaustion and malicious repository instructions. Deterministic gates and owner review matter more than a large speculative framework. Broader model-quality evaluation remains incomplete.
